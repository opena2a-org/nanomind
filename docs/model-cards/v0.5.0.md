## Known Limitations

- Eval set is small (194 samples). Some classes have only 11-14 eval samples, making per-class metrics noisy. Larger eval sets needed for confidence.
- Persistence class has F1=0.9231 (lowest). 2 persistence samples misclassified as privilege_escalation and policy_violation.
- No adversarial robustness testing yet. Adversarial benchmark (Benchmark 7) not implemented.
- Base64 content detection is fragile -- model learned to not flag known patterns but may still FP on novel base64 formats.
- Word-level tokenizer limits ability to distinguish character-level features (e.g., Cyrillic homoglyphs mixed into Latin).

## Decision Log

| Decision | Rationale |
|----------|-----------|
| Fine-tune from v0.4.0 | Preserves learned features, only adjusts for new benign patterns |
| Lower LR (0.0005) | Prevents catastrophic forgetting of attack detection during fine-tuning |
| 106 benign samples | Targeted at specific FP categories identified in benchmark |
| Same tokenizer | Avoids retraining from scratch, maintains consistency |
| Cosine schedule + warmup | Stabilizes early training when starting from pretrained weights |

## Reproduction

```bash
cd ~/workspace/opena2a-org/nanomind

# Step 1: Build v10 corpus (in nanomind-training)
cd ../nanomind-training
python3 scripts/build-v10-corpus.py

# Step 2: Train (fine-tune from v6)
cd ../nanomind
python3 training/scripts/train-tme-mlx.py \
  --corpus-dir ../nanomind-training/corpus/sft-v10 \
  --output-dir training/models-tme-v7 \
  --finetune-from training/models-tme-v6 \
  --epochs 300 --batch-size 64 --layers 8 --d-model 128 \
  --dropout 0.1 --lr 0.0005 --patience 60 --vocab-size 6000

# Step 3: Export ONNX
python3 training/scripts/export-onnx.py --model-dir training/models-tme-v7

# Step 4: Benchmark
cd ../nanomind-training
make benchmark-quick \
  MODEL_PATH=../nanomind/training/models-tme-v7 \
  EVAL_PATH=corpus/sft-v10/eval.json \
  MODEL_VERSION=0.5.0 CORPUS_VERSION=sft-v10
```
